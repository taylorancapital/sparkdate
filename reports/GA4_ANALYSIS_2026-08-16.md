# GA4 Analysis — 2026-08-16 (Nightly Automation)

**This run made zero code changes.** It is a read-only analysis of the GA4/Meta exports sitting
in the Night Tasks folder. No files in `public/`, `api/`, or `lib/` were modified. The only change
in this branch is this report file. Source reading (a read-only clone's `git log`/`show`/`grep`)
was used only to explain the numbers, never to fix anything.

## Data used

21 GA4 CSVs in `Business Plan/files/Night Tasks/` (`download.csv` through `download (20).csv`),
all sharing the header `# 20260519-20260815` (May 19 – Aug 15, 2026): Active Users (Direct vs
Paid), Events Counts, Campaign Performance, a landing-page "Free form" breakdown, Revenue by Item
/ by Source, Checkout Error Breakdown, two separate Checkout/Funnel explorations, three Ecommerce
item-level views (Users by Events, Views→Cart Ratio, View→Cart→Revenue), Segment-by-Device

Tracking. Also used: two GA4 Path Exploration PDF exports (`data.pdf`, window ending Aug 14;
`data (1).pdf`, window ending Aug 15 — the newer of the two is used as current; the older appears
to be a same-session leftover and was left in place, not moved or deleted) and
`meta-insights-2026-08-15.csv`, a direct Meta Marketing API pull (Aug 9–15, campaign level,
generated by the separate nightly PowerShell script at 2026-08-16 02:00 local, a different
collection mechanism/timing than the user-exported GA4 CSVs).

**This is a genuinely fresh export, not a re-read of the pending 08-15 report's data.** The
still-open `claude/ga4-analysis-2026-08-15` branch/PR analyzed a pull whose daily-indexed tables
stopped at day 87 = Aug 13 (20 files, three of them `*-ecommerce.csv`). Tonight's pull has 21 files
(no `-ecommerce` suffix, different report mix), and its daily-indexed tables (Monthly Trends, files
12–15) run one day further, through **day 88 = Aug 14** (verified by counting forward from the
`20260519` start date, same method as every prior report). As with every prior pull, the header
claims the range through Aug 15 but the day-indexed trend tables lag one day behind that; aggregate
tables (revenue, campaign, ecommerce, events) are treated as current through their own totals.

## Headline: the first Meta-pixel-confirmed purchase since direct ad tracking began, landing right after the in-app-browser block was removed

The 08-14 report found **$104.69 spent across 9 Meta campaigns for Aug 7–13, zero `purchase`
actions anywhere** in the platform's own pixel data — a finding independent of GA4's attribution.
Tonight's Meta pull, one week later, is a clean before/after test of the Aug 13 22:01 EDT removal
of the in-app-browser checkout block (PR #165, confirmed in the 08-15 report):

- **Aug 9–15: $160.43 spent, 479 clicks, 11,787 impressions, across the same 9 campaigns — and
  exactly one `purchase` action**, on **"Tellus AfterDark: Singles Edition Retargeting"**
  ($41.37 spend, 102 clicks, 8 `initiate_checkout`, 3 `add_to_cart`, 1 `purchase` /
  `offsite_conversion.fb_pixel_purchase` / `omni_purchase`, all consistent counts for a single
  real transaction, not a dedup artifact).
- This lines up with two independent GA4 signals in the same window: **`Instagram / paid_social`
  shows $27.49 revenue (1 transaction)** in `download (2).csv` — the first non-zero row for any
  `paid_social`-tagged Facebook/Instagram source/medium in at least 8 consecutive reports — and
  **`Tellus AfterDark: Singles Edition` item revenue jumped from $37.98/2 purchases (per the 08-15
  report) to $112.95/5 purchases** this pull (`download (10).csv`), a +3-purchase, +$74.97 swing
  concentrated in exactly the item the Meta retargeting campaign is selling. $24.99 ticket +
  $2.50 service fee = $27.49, matching the GA4 row exactly.
- **Caveat on precision:** the Meta window (Aug 9–15) and the "before" window from the 08-14 report
  (Aug 7–13) overlap on Aug 9–13 and aren't a clean week-over-week pair; of the Meta window's 7
  days, only the back half (Aug 13 evening through Aug 15) is fully post-unblock. No day-by-day
  revenue table was in tonight's export (unlike the 08-15 pull), so the exact day of the 3 new
  Tellus purchases can't be pinned — this read is built from aggregate deltas between reports, not
  a transaction-level trace.

**Read plainly:** this is the strongest evidence yet that the in-app-browser fix is working, but
it is one purchase and one campaign after weeks at zero — not yet a confirmed trend. See "what to
re-check" below.

## Traffic: another all-time-high week, engagement still volatile day to day

`download (18).csv` (Cohorts): the **Aug 9–15 weekly cohort is 475 new users** — the largest
weekly cohort in the dataset by a wide margin (previous best: 270, Jul 26–Aug 1; the 08-14 report's
mid-week partial read of this same week was 352 for Aug 9–13 alone).

Daily engagement rate (`download (14).csv`) is still swinging hard, not settling: **Aug 11: 15.1%
→ Aug 12: 52.4% → Aug 13: 64.9% → Aug 14: 8.3%**. Sessions and active users stayed elevated
throughout (73–101 sessions/day, day 85–88) while engagement rate bounced between roughly 8% and
65% on consecutive days. This is the same instability the 08-14 report flagged as a collapse
(75.9% → 1.3% over Aug 5–13); it hasn't resolved into either a clean recovery or a clean floor —
it's noisy, day-to-day, and worth another week before reading a direction into it.

`in_app_browser_detected` (`download (1).csv`, Events Counts): **924 of 2,843 `session_start`
events (32.5%)**, up slightly from 31.9% in the 08-15 report — roughly flat given the wider window,
consistent with every prior report's caveat on this metric. New this pull: **`in_app_browser_
escape_attempt` fired 36 times** — this event didn't exist before PR #165 (Aug 13, "Escape the
Instagram/Facebook webview on Android") added it; its presence in live telemetry confirms the
escape-intent mechanism is firing in the wild, not just present in source.

## Funnel measurement: same known artifact, re-verified against current source

`download (11).csv` ("Segment by Device", 5-step) again shows mobile users completing "Add to
cart → Begin checkout" at 0% (0 of 21) vs desktop's 40% (2 of 5) — the same shape the 08-15 report
diagnosed as a step-definition artifact, not a live bug: `begin_checkout` only fires on
`public/index.html` (`get_tickets_block`/`sticky_ticket_bar`) and `public/lp.html`, never on
`public/event.html`, while `add_to_cart` only fires on `event.html`/`events.html`. Re-checked
against tonight's clone (latest commit `4928061`, 2026-08-16 02:01) — **still true, nothing in the
Aug 14–16 commits touched this.** The recommendation to rebuild that Explore step using
`checkout_form_started` (which does fire on `event.html`) instead of `begin_checkout` still stands
and still hasn't been made (this is a GA4 Explore config change, not a codebase one, so it's out of
this task's scope either way).

Two separate 2–3-step funnel views (`download (7).csv`: 46 → 15 → 6; `download (19).csv`: 1,841 →
46 → 8) both undercount the real 24 purchases this window, the same standing gap flagged in the
08-14 report — GA4 Explore step definitions still don't match actual transaction volume across
every funnel view in these exports.

## Caveats / method notes

- **Window granularity mismatch, same pattern as every prior report:** all 21 files claim
  `…-20260815`, but the daily-indexed Monthly Trends tables only have data through day 88 = Aug 14.
  Aggregate/item-level tables (revenue, campaign, ecommerce, events) are treated as current through
  Aug 15 by their own totals; daily trend figures above are cited by their actual date, not the
  window label.
- **No day-by-day revenue table in this export** (unlike the 08-15 pull, which had one) — the
  timing of the 5 new transactions within the window is inferred from aggregate deltas between
  reports, not traced to a specific day.
- **Two Path Exploration PDFs present**, one day apart (`data.pdf` ends Aug 14, `data (1).pdf`
  ends Aug 15); the newer is used as current, the older left in place per the rule against moving/
  renaming/deleting source files.
- **Meta insights collection timing:** `meta-insights-2026-08-15.csv` was generated by a separate
  automated pull (2026-08-16 02:00 local) on a rolling 7-day window, not a manual export like the
  GA4 CSVs (timestamped Aug 15 23:49–59) — close but not a simultaneous snapshot with the GA4 data.
- **Prior-report figures are cited from the repo, not memory:** $503.32/19 transactions and the
  Tellus/Good Good Night/Founders Mixer item baselines are from `reports/GA4_ANALYSIS_2026-08-15.md`
  on the still-open `claude/ga4-analysis-2026-08-15` branch (not yet merged to main); the $104.69/
  zero-purchase Meta baseline is from `reports/GA4_ANALYSIS_2026-08-14.md`, merged to main via
  PR #169. Both were read directly from the clone this session, not paraphrased from a summary.
- **Sample size still modest:** 24 transactions total since May 19. Single-transaction and
  single-pixel-event swings (like this report's headline) are large percentage moves in a sample
  this size — directionally meaningful given the specific campaign/item/timing alignment, but not
  yet statistically strong on their own.
- No live network egress was used — no requests were made to sparkdate.date, GTM, GA4's UI, or any
  ad platform. Everything above comes from the CSV/PDF files in the Night Tasks folder and a
  read-only clone/grep/log of the repo (git history read via `git log`/`grep` on a `--depth 50`
  clone, sufficient to cover all commits cited above).
